站点迁移后遇到一个典型故障：服务器在境外，从本地能正常访问，但从国内手机打开却一直超时或报连接被重置。奇怪的是 DNS 解析是对的，IP 也能 ping 通，服务器上的服务全部在跑。这类「看起来哪里都没坏，但就是打不开」的问题，靠逐层剥离变量才能收敛。

## 先把问题拆成几层

一个 HTTPS 请求至少要经过这些环节：

1. DNS 解析：域名 → IP；
2. TCP 连接：本机 → 服务器的三次握手；
3. TLS 握手：客户端发出 ClientHello（其中含明文的域名，即 SNI），服务器返回证书；
4. HTTP 交换：请求与响应。

任何一层被干扰，最终表现都可能是「打不开」。所以第一步不是急着改配置，而是确定失败发生在哪一层。

## 用对照实验切掉变量

最有效的做法是**只改一个变量**，看结果是否翻转。三个对照测试：

| 测试 | 变量 | 结果 | 排除掉的可能 |
|---|---|---|---|
| 直接访问 IP（走 HTTPS） | 去掉域名 | ✅ 通 | 服务器、IP、端口、证书都没问题 |
| 换一个无关域名指向同一 IP | 只换 SNI | ✅ 通 | 说明该 IP 的 TLS 通路正常 |
| 访问原域名 | 保持原样 | ❌ 重置 | 问题锁定在「这个域名本身」 |

第三行的意义在于：同一台服务器、同一个 IP、同一个 443 端口，前面两个都通，只有用原域名时失败——那么 DNS、服务器、证书、端口全部可以排除，剩下的可能就是「域名相关的干扰」。

## 抓包给出机制层面的证据

确认「域名相关」之后，还需要知道**它是怎么失败的**，因为不同机制对应不同解法。在服务器上抓包，读连接的生命周期：

- 客户端的 ClientHello **确实到达了服务器**，且 SNI 字段是原域名；
- 服务器**正常回了证书**；
- 随后立刻收到一个 RST 包，把连接掐断——而且这个 RST 到的时机极快，服务器还没来得及发出任何应用数据。

再看这个 RST 的报文特征：它的 TTL 与客户端真实报文的 TTL 明显不同（例如一个是 170，另一个是 46）。TTL 由发送方操作系统的初始值决定，同一台机器发出的包 TTL 应当一致；TTL 差异说明这个 RST **不是客户端发的，而是链路上某个设备伪造注入的**。

到这里机制就清楚了：是中间设备识别到 TLS 握手里的域名后，注入伪造的 RST 阻断连接。这解释了为什么「DNS 对、IP 通、服务器健康」，页面却打不开。

## 几个容易踩的坑

**裸 IP 的 HTTPS 测试会误判。** 用浏览器直接访问 `https://<IP>` 时，多数浏览器不发 SNI。如果服务器配置了「按域名匹配证书」，就会返回默认证书或直接握手失败，报出类似 `ERR_SSL_PROTOCOL_ERROR` 的错误。这个错误是**测试方法本身**造成的，不代表服务器有问题——需要在服务器端配置默认证书（`default_sni`）后重测才有意义。

**ping 通不代表端口可用。** ICMP 与 TCP 是两条不同的路径，很多环境会单独处理。要验证端口，用 TCP 层的探测（`nc -vz`、`curl --max-time`），而不是 `ping`。

**「国外能访问」不是排除项，而是必要条件但非充分条件。** 服务器健康、全球节点可达，只能证明服务本身没问题；国内可达性需要国内网络环境的真实验证。

**IPv6 会引入一条独立的失败路径。** 域名若同时有 A 和 AAAA 记录，而客户端优先尝试 IPv6、服务器却没有 IPv6 监听，就会表现为「部分网络能开、部分不能」。排查时先看清 `dig AAAA` 有没有记录。

**HTTP/3（QUIC）是常被忽略的变量。** 它跑在 UDP 443 上，而部分运营商网络对 UDP 的处理与 TCP 不同。出现过「HTTP/1.1 正常但浏览器报 SSL 协议错误」的情况，原因就是客户端尝试 QUIC 失败。需要时可在服务器显式禁用 h3，只保留 h1/h2。

## 收敛后的处理方向

机制明确之后，可选方向就有限且可验证了：

1. **更换访问域名**：绕开被针对的名字，换一个不受影响的域名即可，服务器不用动；
2. **验证新域名是否可用**：仍然用对照实验——先确认它能到达你的服务器，再看能否完成 TLS 握手；
3. **不要先换 IP**：如果换域名就通，说明 IP 是干净的，换 IP 是无效操作。

最后一条经验：**在改任何配置之前，先拿到「失败发生在哪一层」的证据。** 有了分层结论，后续每一步修改都能被验证；没有它，就容易在服务器配置上反复试错，而真正的原因在链路上。

---

排查的核心不是记住某个具体现象，而是保留一套「只改一个变量」的对照方法。环境会变，域名会变，但把故障范围逐层收敛的思路是稳定的。
